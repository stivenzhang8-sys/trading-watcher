# watcher — no-AI price watcher (read-only, public data, never places orders)
- `watcher.py` reuses tools/tp.py (`scan_crypto`, `scan_stocks`, `trend_metrics`, trades.csv reader).
- Crypto (17 tp.py pairs, Kraken public) every 10 min 24/7; stocks (tools/watchlist.txt, 231-name universe, Yahoo via the shared tp.py cache, ~3-10 s per cycle) every 15 min
  only while open: EU suffixes (.DE .AS .PA .MI .MC ...) 9:00-17:30 Rome, US 9:30-16:00 New York (15:30-22:00 Rome), weekdays. No holiday calendar.
- Flags: `candidate` (tp scan candidate, on transition), `near_candidate` (all other conditions met and only
  price<SMA20 or mom20<=0 fails by <=1%), positions: `reached_1.5R`, `trail_start_2R` (once per trade), `near_stop` (<=1% above stop).
- Cost control: 6h cooldown per account:symbol:reason, max 6 successful wakes per Rome day, skip if a scheduled
  session is due within 30 min (Kraken :58 of 2,5,..,23 daily; T212 :21 of 9,11,..,21 weekdays).
  `near_stop` ALWAYS wakes (ignores both the cap and the session-due skip; its 6h cooldown still applies).
- Flags suppressed by the cap or session-due skip go to `pending.jsonl` (deduped per account+symbol+reason,
  keeps first_ts/ts/count). Sessions should start with `python3 watch/pending.py list --account kraken|t212`
  and finish with `python3 watch/pending.py clear --account kraken|t212` (optional `--symbol`, `--reason`).
- Candidate flags fire on transitions only; a symbol seen for the first time (fresh start, newly added to the
  watchlist) is recorded silently, so existing static candidates don't burn wakes (sessions see them anyway).
- Webhook: env `WATCH_WEBHOOK_URL`, `WATCH_WEBHOOK_AUTH` (an `Authorization:` prefix is stripped; else used as-is).
  Daemon starts via `bash -lc` so it inherits them; optional fallback file `watch.env` (KEY=VALUE, chmod 600).
- Files: state.json, alerts.jsonl, pending.jsonl, watcher.log (rotating 1MB x3), watcher.pid, supervisor.pid/log, daemon.out.
- Run: `bash ensure_running.sh` (start + 5-min supervisor loop; cron is not installable here), `bash ensure_running.sh --stop`.
- Test: `python3 test_watcher.py`; `bash -lc 'python3 watcher.py --once --dry-run --all-markets'`; `python3 watcher.py --test-post`.

## Stock universe and data cache
- `tools/watchlist.txt` is generated by `python3 tools/universe/build_universe.py` from `tools/universe/candidates.txt`
  (S&P 100 + liquid US tech, DAX 40, CAC 40, AEX/BEL majors, FTSE MIB, Euro Stoxx 50 rest, 17 Xetra UCITS ETFs).
  Filters: Yahoo daily data (>=130 bars); 20-day avg traded value >= 250M EUR (US), 15M EUR (EU stocks), 1M EUR (ETFs);
  a Trading 212 EUR instrument (US: `_US_EQ`) from `tools/cache/t212_instruments.json`. Verdict per symbol in
  `tools/universe/universe.csv` (incl. the T212 ticker). Re-run monthly or after editing candidates.
- Refresh the T212 instrument list (read-only, 1 request, keys from env, never printed):
  `bash -lc 'cd /workspace/trading && python3 -c "import sys,json;sys.path.insert(0,\"tools\");import tp;json.dump(tp.t212_get(\"/equity/metadata/instruments\"),open(\"tools/cache/t212_instruments.json\",\"w\"))"'`
- Cache (`tools/cache/yahoo/`, shared by the watcher and `tp.py scan stocks`): daily bars per symbol are fetched once per
  Rome day and once more after the session that was open at fetch time has closed (4 parallel workers, ~10 s cold for 231).
  Each cycle fetches last prices in batches of 20 via Yahoo spark (12 requests) - warm cycle ~3 s.

## Cloud watcher (GitHub Actions) - primary since 2026-11-01
- Repo (public, so Actions minutes are free): https://github.com/stivenzhang8-sys/trading-watcher
  Workflow `.github/workflows/watcher.yml`: cron `*/10 * * * *` + `workflow_dispatch` (input `dry_run`, default true).
  GitHub may delay or skip scheduled runs (often 5-20 min late under load); `keepalive.yml` runs monthly so the
  schedule isn't disabled after 60 days without activity (re-enables both workflows + pushes `.github/keepalive`).
- Each run = `python3 watch/watcher.py --cloud --state-dir $RUNNER_TEMP/wstate`: one pass, not a daemon.
  Crypto scan every run (24/7); stocks only while their market is open (same hours as above; every 10 min instead of 15);
  position checks (+1.5R, +2R trail start, within 1% of stop) on every run for open crypto positions and while the
  market is open for T212 positions. Candidate flags fire on transitions; first sightings are recorded silently.
- Positions: secret `POSITIONS_JSON` (JSON list: id, account, pair, entry, stop, initial_stop, qty, level_1_5R,
  trail_start_2R). After ANY position change logged in trades.csv run `bash watch/sync_positions.sh`
  (rewrites the secret from the open trades.csv rows via `gh secret set`; `--print` shows the JSON locally only).
- State: state.json (cooldowns, wakes, scan status, levels fired) + pending.jsonl + alerts.jsonl in one tarball,
  AES-256 encrypted with secret `WATCH_STATE_KEY` (openssl, pbkdf2), saved to the Actions cache as
  `watch-state-<run_id>-<attempt>` and restored from the newest `watch-state-*` (runs never overlap: concurrency group).
  Old state caches are pruned hourly (newest 5 kept). Cache entries unused for 7 days are evicted by GitHub; if the state
  is lost the watcher simply starts fresh (first sightings silent, cooldowns reset). Nothing is committed to the repo.
  Yahoo daily bars: `tools/cache/yahoo` in the Actions cache, saved only when the content changed (~1-3x/day).
- Cooldowns (6h per account:symbol:reason), daily cap 6 wakes per Rome day (near_stop bypasses), session-due skip:
  identical to the box watcher, but counted separately (box copy is log-only, see below).
- Pending flags in the cloud: flags suppressed by the cap or a due session go to the cloud pending queue (in the
  encrypted state; deduped per account+symbol+reason, count/first_ts kept). They are delivered in the webhook payload:
  (1) every successful wake carries the same-account pending items in a `pending` field, and they are then cleared;
  (2) if items suppressed by the cap are still waiting, one `pending_batch` wake per account (symbol `PENDING`,
  reason `pending_batch`, items in `pending`) is sent as soon as the cap allows again (normally the first run after
  Rome midnight) and no scheduled session of that account is due within 30 min; it counts as one wake.
  Items only suppressed by `session_due` never trigger a batch (that session runs its own scan). Undelivered items
  expire after 24h. `pending.py list` on the box therefore stays empty while the cloud watcher is active; read the
  `pending` field of the wake payload instead. Cloud payloads carry `source: "github-actions"`.
- Public logs: position flags are logged as `FLAG position check -> <action>` without symbol, prices or levels.
- Secrets (set from the box with `gh secret set ... < stdin`, never printed): `WATCH_WEBHOOK_URL`, `WATCH_WEBHOOK_AUTH`,
  `POSITIONS_JSON`, `WATCH_STATE_KEY` (random, only used by the workflow).
- Manual run: `gh workflow run watcher.yml -R stivenzhang8-sys/trading-watcher -f dry_run=true` (no POST, state untouched)
  or `-f dry_run=false` (real pass). Runs: `gh run list -R stivenzhang8-sys/trading-watcher -w watcher.yml`.
- Box copy while the cloud is active: `watch.env` has `CLOUD_WATCHER=1` -> the box daemon keeps scanning and logging
  but never POSTs (flags logged as `not_configured (box log-only: CLOUD_WATCHER=1)`, no pending.jsonl entries).
  The flag is re-read every cycle (no restart needed). Fallback if GitHub Actions breaks: set `CLOUD_WATCHER=0` in
  watch.env (or delete the line), then `bash ensure_running.sh`; disable the cloud schedule with
  `gh workflow disable watcher.yml -R stivenzhang8-sys/trading-watcher` to avoid double wakes.
- Code changes: /workspace/trading is the git checkout (whitelist .gitignore: only watcher/tp/watchlist files are
  published; journals, trades.csv, state, watch.env, tools/account.local.json never). `git pull --rebase` before
  pushing (keepalive commits monthly). Account-size values for tp.py live in tools/account.local.json (box only).
